# Как связать движок с игрой

Четыре сценария: (1) открыть готовый `neirogh.story.rbxl` и играть, (2) собрать
демо-сюжет через Rojo, (3) вживить движок в своё место из `.rbxlx`, (4) взять только
сюжет и написать свой UI.

---

## 1. Что где лежит

```
story/story.json                 сюжет: сцены, флаги, предметы, концовки
tools/build-story.mjs            проверка + генерация Luau и графа
roblox/src/ReplicatedStorage/Shared/StoryData.lua     ← генерируется, руками не правим
roblox/src/ReplicatedStorage/Shared/StoryEngine.lua   ← логика, правим
roblox/src/ServerScriptService/StoryServer.server.lua ← сессии игроков
roblox/src/ReplicatedStorage/Shared/Cinema.lua        ← циклические анимации
roblox/src/ReplicatedStorage/Shared/TeleportDirector.lua ← проверка телепорта
roblox/src/StarterPlayer/StarterPlayerScripts/StoryClient.client.lua ← UI
game/place-map.json              координаты и вывески, снятые с neirogh.rbxl
game/layout.json                 связанность моделей и арена финала
tools/place-import.mjs           .rbxl → place-map.json (нужен rbx-dom)
tools/analyze-place.mjs          place-map.json → layout.json + docs/КАРТА.md
tools/build-place.mjs            карта + скрипты → один neirogh.story.rbxl
roblox/src/ReplicatedStorage/Shared/WorldKit.lua  раскладка сцен по координатам карты
tools/test-place-file.mjs        проверка собранного .rbxl
neirogh.rbxl                     исходная карта (не трогаем)
neirogh.story.rbxl               готовый файл: карта + новелла
uploader/index.html              страница загрузки файла игры в репозиторий
```

Пересобрать данные сюжета:

```bash
npm run build       # story.json → StoryData.lua + docs/ГРАФ.md, с проверками
npm test            # + синтаксис Luau + 80 логики + 104 плеера + 34 карты + 26 .rbxl + 41 загрузчика
npm run map         # пересобрать карту из neirogh.rbxl и связи по координатам
npm run place       # пересобрать neirogh.story.rbxl (нужен rbx-dom)
```

## 2. Совсем без сборки: один .rbxl

`neirogh.story.rbxl` — это исходная карта `neirogh.rbxl` плюс шесть скриптов
новеллы. Всё уже разложено по сервисам:

| Куда | Что |
|---|---|
| `ReplicatedStorage.Shared` | `StoryData`, `StoryEngine`, `Cinema`, `TeleportDirector` |
| `ServerScriptService` | `StoryServer` (Script) |
| `StarterPlayer.StarterPlayerScripts` | `StoryClient` (LocalScript) |

Открой файл в Studio → **Play**. Это игра по карте, а не меню: у каждой сцены есть
точка в мире, к ней ведёт метка `▼` и луч, при подходе сцена срабатывает сама.
Внизу — субтитры с печатной машинкой и выборами, сверху — глава, здоровье и инвентарь.

| Элемент | Что делает |
|---|---|
| метка `▼` + луч | точка текущей сцены; надпись «поговорить: Демид», если сцену ведёт живой НПС |
| субтитры снизу | реплика, выборы, подсказка «ещё N шагов» |
| `F` | удар: ближайший НПС отлетает, идут искры |
| `Space` / оранжевая кнопка | телепорт последней главы (переносит в огненный зал) |

Пересборка:

```bash
npm i --no-save rbx-dom
npm run build && npm run place
```

`tools/build-place.mjs` удаляет одноимённые узлы перед вставкой, поэтому сборка
идемпотентна. `tools/test-place-file.mjs` дополнительно сверяет `Source` каждого
скрипта с файлами в `roblox/src` — если файл отстал, тест падает с подсказкой
`npm run place`.

## 3. Мир: как сцены ложатся на карту

`WorldKit.lua` — чистый модуль (ни `Workspace`, ни `Players`), поэтому его поведение
покрыто тестами.

```lua
local WorldKit = require(ReplicatedStorage.Shared.WorldKit)
local world = WorldKit.new(StoryData)

world.plan["ch4_teleport"]     -- { pos = {x,y,z}, zone = "z4_c7", npc = "Некит", act = 4 }
world:point("final_choice")    -- та же запись или nil
world:autoChoice("start")      -- 1, если у сцены один безусловный выбор (идти самому не надо)
world:distanceTo("start", root.Position)
world:findNpc("demid", pos)    -- ближайший живой Демид в радиусе 220
world:stages()                 -- акт → зоны маршрута
```

Маршрут задаётся в `story.json`:

```json
"meta": {
  "map": {
    "route": [
      { "act": 1, "zone": "spawn" },
      { "act": 1, "zone": "z3_c6" },
      { "act": 2, "zone": "z0_c0" },
      { "act": 3, "zone": "z4_c8" },
      { "act": 4, "zone": "z4_c7" }
    ]
  }
}
```

Сцены акта равномерно раскладываются вдоль ломаной между зонами этого акта
(по длине, а не по числу точек). Если в сцене говорит персонаж, который есть на
карте живой моделью (`StoryData.world.cast`), точка сцены переезжает к этому НПС —
в радиусе `WorldKit.NPC_PULL` (220 юнитов).

Как сервер водит игрока:

1. Каждые 0.25 с смотрит расстояние до точки текущей сцены.
2. Если у сцены один безусловный выход и игрок в радиусе `WorldKit.REACH` (14) —
   выбор применяется автоматически, сцена едет дальше.
3. Если выходов несколько — игрок жмёт кнопку внизу, но подсказка показывает,
   сколько ещё идти.
4. В акте IV включается бой: камера вздрагивает, здоровье понемногу падает,
   `F` отбрасывает ближайшего НПС.

Собрать заново после правок маршрута:

```bash
npm run build   # story.json + layout.json → StoryData.lua (world, order)
npm run place   # → neirogh.story.rbxl
```

## 4. Быстрый старт в Studio через Rojo (демо-сюжет)

**Вариант А — Rojo** (рекомендую, если ставишь плагин):

```bash
npm i -g rojo
rojo serve roblox/default.project.json
```

В Studio: плагин Rojo → Connect. Появятся `ReplicatedStorage.Shared`,
`ServerScriptService.StoryServer`, `StarterPlayer.StarterPlayerScripts.StoryClient`.

**Вариант Б — руками** (без плагинов):

1. `ReplicatedStorage` → папка `Shared` → ModuleScript `StoryData`, вставить
   содержимое `StoryData.lua`; ModuleScript `StoryEngine` — содержимое `StoryEngine.lua`.
2. `ServerScriptService` → Script `StoryServer` — `StoryServer.server.lua`.
3. `StarterPlayer/StarterPlayerScripts` → LocalScript `StoryClient` — `StoryClient.client.lua`.
4. Play. Ремоуты (`StoryRemotes`) создаются сервером автоматически.

> `StoryData.lua` — около 2300 строк на 95 сцен. Если вставляешь руками, копируй
> целиком, не по частям. Проще взять готовый `neirogh.story.rbxl` из раздела 2.

## 5. Вживить в своё место (после загрузки `.rbxlx`)

Загрузи файл через `uploader/index.html` — скрипты распакуются в
`game/scripts/<имя места>/…` с суффиксами Rojo. Дальше:

### Шаг 1. Оставь один источник правды

Не держи текст сцен в скриптах места. Весь текст — в `story/story.json`, всё
остальное читает `StoryData`. Если в твоей игре уже есть свои диалоги — перенеси их
в JSON (сцена = узел, реплика = `text`, варианты ответа = `choices`).

### Шаг 2. Подключи движок

`StoryEngine` ничего не знает про Roblox-сервисы, поэтому его можно вызвать откуда
угодно — из серверного скрипта локации, из `ProximityPrompt`, из NPC:

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Shared = ReplicatedStorage:WaitForChild("Shared")
local StoryEngine = require(Shared.StoryEngine)
local StoryData = require(Shared.StoryData)

local engine = StoryEngine.new(StoryData)
engine:enter(engine.state.nodeId)          -- войти в стартовую сцену

-- показать текущую сцену
local view = engine:current()
print(view.speaker, view.text)
for _, choice in ipairs(view.choices) do
    print(choice.index, choice.text)
end

-- выбрать (index — номер выбора в сцене, не в отфильтрованном списке)
local ok, resultOrReason = engine:choose(2)
if not ok then
    warn("нельзя:", resultOrReason)         -- например «нужно: Ключ-карта смены 9»
end
```

Важно: **`choose` принимает номер из `story.json`** (поле `choice.index` в `view`).
Фильтрация закрытых выборов уже сделана движком — не перенумеровывай.

### Шаг 3. Привяжи мир к сюжету

| В игре | В коде |
|---|---|
| Подошёл к терминалу | `engine:choose(index)` → `render(engine:current())` |
| Взял предмет | `engine.state.items.keycard = true` (или `onEnter.give` в сцене) |
| Поговорил с NPC | отдельная сцена в JSON, `speaker` = ключ персонажа |
| Открыл дверь | `requires.flags` в выборе, а не `if` в скрипте двери |
| Подошёл к месту сцены | `WorldKit`: точка из `world.plan[sceneId]`, радиус `WorldKit.REACH`; один безусловный выбор применяется сам |
| Рядом живой НПС | `speaker` сцены → `StoryData.world.cast` по имени; точка сцены переезжает к модели |
| Финальная зона | сцена с `"ending": "ash"` (и другие) — UI сам покажет экран концовки |
| Телепорт | поле `teleport` у сцены: `target`, `requires`, `arrival`; сервер переносит персонажа |
| Анимация | поле `animations` у сцены: `{id, fps, loop, frames}`; проигрыватель — `Cinema.lua` |

Проверки условий живут **в данных**, а не в коде. Тогда `npm run build` видит всё
и предупреждает о мёртвых ветках.

### Шаг 4. Свой UI вместо демо

Демо-клиент — это `StoryClient.client.lua`. Если у тебя уже есть красивый
интерфейс, замени только рендер:

```lua
local function render(view)
    sceneTitle.Text = view.scene
    speakerName.Text = view.speaker
    speakerName.TextColor3 = Color3.fromHex(view.color)
    body.Text = view.text

    for _, button in ipairs(choicesFrame:GetChildren()) do
        if button:IsA("TextButton") then button:Destroy() end
    end

    for _, choice in ipairs(view.choices) do
        local button = template:Clone()
        button.Text = choice.text
        button.Activated:Connect(function()
            Choose:FireServer(choice.index)   -- серверный путь, как в демо
        end)
        button.Parent = choicesFrame
    end
end
```

Серверная часть (`StoryServer.server.lua`) остаётся: она держит по одному
`StoryEngine` на игрока, ограничивает частоту выбора и не отдаёт клиенту внутреннее
состояние напрямую.

### Шаг 5. Сохранение прогресса

`engine:serialize()` возвращает таблицу, которую можно положить в `DataStore`:

```lua
local DataStoreService = game:GetService("DataStoreService")
local store = DataStoreService:GetDataStore("StoryProgress_v1")

local function load(player)
    local ok, data = pcall(function() return store:GetAsync(tostring(player.UserId)) end)
    local engine = StoryEngine.new(StoryData, ok and data or nil)
    if not engine.state.visited[engine.state.nodeId] then
        engine:enter(engine.state.nodeId)
    end
    return engine
end

local function save(player, engine)
    pcall(function() store:SetAsync(tostring(player.UserId), engine:serialize()) end)
end
```

`StoryEngine.new(data, savedState)` сам проверит, что сохранённая сцена ещё
существует, и откатится на старт, если сюжет успел измениться.

> При смене структуры сюжета меняй имя DataStore (`_v2`, `_v3`) — старые сохранения
> не должны утаскивать игрока в удалённые сцены.

## 6. Публичный API движка

| Метод | Что делает |
|---|---|
| `StoryEngine.new(StoryData, savedState?)` | создать сессию |
| `engine:enter(nodeId)` | войти в сцену, применить `onEnter` |
| `engine:current(showLocked?)` | данные для отрисовки (текст с вариантами флагов, выборы, концовка) |
| `engine:choose(index)` | сделать выбор → `true, view` или `false, причина` |
| `engine:check(requires)` | проверить условие `{flags, notFlags, items}` |
| `engine:hasFlag(id)` / `engine:hasItem(id)` | проверки |
| `engine:serialize()` / `engine:restart()` | сохранение и рестарт |
| `engine:progress()` | `{visited, total, ending, flags, items}` |
| `engine:node(id?)` | сцена по id или текущая |

Поля `view`: `id, act, chapter, scene, speaker, color, text, choices[], isEnding,
ending, animations[]`, `teleport` (если у сцены есть телепорт), `items`, `world`
(`pos`, `zone`, `npc`, `distance`, `ready`, `auto`) и `progress` (если добавил сервер).

### Мир и НПС

| Метод | Что делает |
|---|---|
| `WorldKit.new(StoryData)` | строит `plan`: у каждой сцены точка в мире |
| `world:point(sceneId)` | `{pos, zone, act, npc}` или nil |
| `world:autoChoice(sceneId)` | номер единственного безусловного выбора |
| `world:distanceTo(sceneId, position)` | сколько идти |
| `world:findNpc(speaker, pos)` | ближайший живой НПС этого персонажа |
| `world:stages()` | маршрут по актам (`from` → `to`) |

Маршрут задаётся `story.meta.map.route` (см. раздел 3). Если живые модели НПС
не нужны — достаточно убрать `cast` из `StoryData.world`: сцены останутся на
маршруте, просто без привязки к конкретной модели.

### Телепорт последней главы

```lua
-- server: координаты берутся из StoryData, клиент присылает только id сцены
local plan = TeleportDirector.plan(node, engine.state)
local ok, reason = TeleportDirector.availability(plan.definition, engine.state)
root.CFrame = CFrame.new(target[1], target[2] + 4, target[3])
engine:enter(plan.definition.arrival)   -- сюжет продолжается на арене
```

### Анимации без остановки

```lua
local cinema = Cinema.new(view.animations, 4)
RunService.Heartbeat:Connect(function(dt)
    for _, frame in ipairs(cinema:advance(dt)) do
        label.Text = frame.text      -- последний кадр → снова первый, loops += 1
    end
end)
```

## 7. Частые ошибки

| Симптом | Причина |
|---|---|
| Выбор не срабатывает | клиент передал номер из отфильтрованного списка, а не `choice.index` |
| Текст без подстановок вида `$keycard` | предмет не объявлен в `items` — движок оставит `$keycard` как есть |
| `StoryData` не найден | папка `Shared` не в `ReplicatedStorage` или модуль назван иначе |
| Сцены не совпали с графом | забыл `npm run build` после правки JSON |
| Игрок застрял | сцена без `choices` и без `ending` — сборщик помечает это как тупик |
| Кнопка телепорта серая | нет предмета из `teleport.requires.items` (в финале — `plate`) |
| Анимация застыла на последнем кадре | у анимации `loop = false`; для бесконечной нужно `loop: true` |
| Телепорт не сработал | `placeId` не совпал с `game.PlaceId` и `TeleportService` не смог — персонаж всё равно перенесён в координаты арены |

## 8. Проверки перед публикацией

```bash
npm test
```

Сборщик падает, если: есть висячая ссылка `goto`, недостижимая сцена или концовка,
тупик, флаг без проверки, предмет без выдачи. Это дешёвый способ не выпустить
сломанную ветку.

Дальше по цепочке:

| Набор | Что ловит |
|---|---|
| `tools/check-syntax.mjs` | синтаксис всех `.lua` в `roblox/src` |
| `tools/run-luau-tests.mjs` | 94 проверки движка и мира на настоящем Luau |
| `tools/test-story-player.mjs` | 104 проверки прохождения: выборы, флаги, все концовки |
| `tools/test-place-map.mjs` | 34 проверки карты: кластеры, телепорты, огонь |
| `tools/test-place-file.mjs` | 31 проверка `neirogh.story.rbxl`: файл собран, скрипты внутри и не устарели |
| `tools/test-uploader.mjs` | 41 проверка загрузчика |

`npm test` пересобирает `neirogh.story.rbxl` перед проверкой — отдельно запускать
`npm run place` не нужно, если только вы не правили карту.
